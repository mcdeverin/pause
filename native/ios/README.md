# Xcode add-ons for the iPhone app

The iOS project is generated by Base44, so it isn't in this repo. These files and
steps are what to add in Xcode after generating it, alongside the Watch app,
HealthKit and CoreHaptics work that already lives there.

Nothing in this folder is part of the web build.

## 1. Firebase (Google Analytics for the app)

1. Drag `GoogleService-Info.plist` (from Firebase / GA4) into the `App` folder in
   Xcode. Tick **Copy items if needed** and the **App** target only.
   Never commit this file to GitHub.
2. File → Add Package Dependencies → `https://github.com/firebase/firebase-ios-sdk`.
   Add **FirebaseAnalytics** only. If **FirebaseAnalyticsWithoutAdIdSupport** is
   offered, pick that instead, so the advertising ID is never touched.
3. In `App/Info.plist` add `FIREBASE_ANALYTICS_COLLECTION_ENABLED` (Boolean) = **NO**.
   Firebase then collects nothing until the app's consent rules turn it on.
4. In `AppDelegate.swift`:

   ```swift
   import FirebaseCore            // at the top

   // in application(_:didFinishLaunchingWithOptions:), before `return true`
   FirebaseApp.configure()
   ```

## 2. Native plugins

1. Add `AnalyticsBridgePlugin.swift` and `MainViewController.swift` (this folder)
   to the `App` folder, App target.
2. In `Main.storyboard`, select the Bridge View Controller and set its Custom Class
   to `MainViewController`.
3. If `CoreHapticsPlugin` is already registered elsewhere, delete its line in
   `MainViewController.swift`.

## 3. Check it

1. Run on a real iPhone. In Xcode, Edit Scheme → Run → Arguments, add
   `-FIRDebugEnabled`, then open GA4 → Admin → DebugView.
2. Fresh install outside Europe: tap **Begin your journey** on the first screen.
   `first_open` / `session_start` should appear, then `breathing_session_started`
   after a session.
3. About → switch off **Share anonymous usage**: events stop.
4. With the phone's time zone set to a European city, a fresh install shows the
   Allow / No thanks banner and nothing is sent until **Allow**.

## 4. App Store Connect

Update the App Privacy answers to match Google's list for Analytics
(support.google.com/analytics/answer/10285841), typically: Identifiers (Device ID),
Usage Data (Product Interaction), Purchases (Purchase History), Location (Coarse),
Diagnostics, each **not linked to the user** and **not used for tracking**, purpose
**Analytics**. Add PostHog's anonymous usage events under Usage Data too.
